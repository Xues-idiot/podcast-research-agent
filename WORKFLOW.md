# Echo (播客研究Agent) - 自主工作流

> **产品定位：让播客内容真正变成你的知识**
> **杀手锏：时间戳导航 + 对话式回顾 + Anki导出**

---

## 核心原则：杀手锏优先

> 每个功能都要问：这个是杀手锏吗？不是的话，别花太多时间

**Echo的杀手锏（必须完美）**：
1. **时间戳导航** - 关键时刻高亮，点击跳转播放，波形同步
2. **对话式回顾** - 基于播客内容提问，引用溯源到具体时间
3. **知识卡片导出** - 带时间戳的引用，Anki格式支持

**为什么是杀手锏？**
- 时间戳导航：看播客的核心体验，NotebookLM没有
- 对话式回顾：不是关键词搜索，是真正理解内容
- Anki导出：看完不是忘，而是记住

**必须思考的问题**：
1. **这个功能是杀手锏吗？** 如果不是，别花太多时间
2. **比NotebookLM好在哪？** 中文优先 + 时间戳 + 对话
3. **用户为什么要用Echo而不是NotebookLM？** 必须能回答这个问题

**常见错误**：
- ❌ 做了很多功能但没有一个是杀手锏级别的
- ❌ 做了P2功能但P0功能体验很差
- ❌ 觉得"功能有就行了" - **杀手锏必须是完美的**
- ❌ 觉得"没什么可优化的" - **杀手锏永远有优化空间**

### 循环迭代机制

> 每次循环结束后，检查是否还有可改进匹配项

```
                        ↓ 循环结束
                        │
        ┌───────────────┴───────────────┐
        ↓                               ↓
   ┌─────────────────────────────────┐   ┌────────────────────┐
   │ 检查：还有可改进的匹配项吗？      │   │ 循环已达 10次？     │
   │ - 功能架构图中的模块还没实现完？   │   │ 暂停，等待用户新任务 │
   │ - 参考项目中还有可借鉴的设计？     │   └────────────────────┘
   │ - 代码还有优化空间？               │
   │ - 测试还有不通过的地方？           │         ↓
   └─────────────────────────────────┘   ┌────────────────────┐
        ↓                               │ 暂停，等待用户新任务 │
   ┌────────────┐                       └────────────────────┘
   │ 有，       │
   │ 说明哪些   │
   │ 还没做好   │
   └────────────┘
        ↓
   ┌─────────────────────────────────────────┐
   │ 继续迭代：回到对应步骤继续改              │
   │ - 功能模块没实现完 → 步骤3（实现代码）   │
   │ - 设计有更好方案   → 步骤1（研究参考）   │
   │ - 代码需优化       → 步骤3（实现代码）   │
   │ - 测试不通过       → 步骤4（测试验证）   │
   └─────────────────────────────────────────┘
        ↓
    回到"步骤0: 理解功能需求"继续循环
```
